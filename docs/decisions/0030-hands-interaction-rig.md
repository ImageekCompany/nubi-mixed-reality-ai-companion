# 0030. Hand-tracked XR rig: the XRI Hands Interaction Demo rig variant

- Status: accepted
- Date: 2026-11-01

## Context
- Reported from the headset: "I didn't see my hands and couldn't control the game with hands." Requirement 12 (architecture, Accessibility) makes hands the primary input.
- `Main.unity` used the XRI 3.6.1 Starter Assets rig, `XR Origin (XR Rig).prefab`. Its `XRInputModalityManager` binds only `m_LeftController`/`m_RightController`; `m_LeftHand`/`m_RightHand` are empty. When the XR Hands subsystem tracks a hand, the manager switches that side to `TrackedHand` and deactivates the controller object (`XRInputModalityManager.cs:430-445`), and with no hand object nothing replaces it. So with hands there was no hand mesh, no ray, no poke and no UI input, only the pinch push-to-talk, which reads the hand subsystem directly.
- The same deactivation broke the pinch gating: `PinchPushToTalk.leftHandRay`/`rightHandRay` pointed at the controllers' Near-Far interactors, which are inactive in hand mode, so "hovering UI" was always false and pinching a Settings button would also have started a turn.
- The OpenXR side was already right: `HandTracking`, `MetaHandTrackingAim` and `HandInteractionProfile` are enabled for Android, and the merged manifest of the last build has `com.oculus.permission.HAND_TRACKING` and `oculus.software.handtracking` (`required=false`), both added by XR Hands' `ModifyAndroidManifest` when `MetaQuestFeature` and `HandTracking` are on.
- Reference: the Lines project (Quest 3, hands working) uses the same rig variant from the XRI Hands Interaction Demo sample.

## Decision
- **Rig.** Import the XRI 3.6.1 sample *Hands Interaction Demo* and its dependency, the XR Hands 1.9.0 sample *HandVisualizer*, at the Package Manager's paths (`Assets/Samples/XR Interaction Toolkit/3.6.1/Hands Interaction Demo`, `Assets/Samples/XR Hands/1.9.0/HandVisualizer`), with their original GUIDs. Only the XRI sample is committed (Licensing, below). The scene's rig instance is switched to `XR Origin Hands (XR Rig).prefab`, a variant of the Starter rig, with `PrefabUtility.ReplacePrefabAssetOfPrefabInstance` (match by hierarchy, keep overrides). Every scene override and reference survived the switch: camera clear and clip planes, floor tracking origin, locomotion off, the AR managers added to the origin and camera, and the `SceneRefs` bindings.
- **What the variant adds** (sample code, unmodified): `Left Hand`/`Right Hand` objects bound to the modality manager, each with a hand Near-Far interactor (pinch selects, UI press), a hand Poke interactor, `MetaSystemGestureDetector` (interactors off during the Horizon OS palm-up menu gesture) and `PokeGestureDetector`; a `HandVisualizer` that activates the Quest or Android XR hand mesh for the detected layout; XR Hands' `XRHandSkeletonDriver` + `XRHandMeshController` on the Quest mesh, which hides it while the hand is untracked; and a One Euro joint filter.
- **Material.** The sample's `Unity_Hand_Medium` (transparent, edge highlight, finger affordance colours) with its depth-only pre-pass, as shipped and as in Lines. It blends with the passthrough instead of covering the real hand with an opaque glove.
- **Our wiring.** `PinchPushToTalk` rays → the hand Near-Far interactors. The hand Poke interactors get the controller pokes' interaction layers (`Default | NubiPoke`), so poking Nubi with a finger raises `InteractionSignals.Poke`. `ControllerPushToTalk`, `XrUserPoseProvider` (pointing ray and hand key points from the XR Hands joints) and the controller objects are unchanged.
- **Pruned on import.** `HandsDemoScene` (its scene, lightmaps and reflection probe), `DemoAssets` and `Prefabs/InteractionAffordance.prefab` (used only by demo objects). `DemoAssets` needs the Video module, which the project does not include, so the full sample does not compile here; nothing the rig uses references these files.
- **Self-test signal.** `HandTrackingMonitor` (`Jolly.XR.Hands`) logs `evt=hands.subsystem`, `evt=hands.tracked left= right=` and `evt=hands.visual left= right=` on change, so a headless device run shows the hand subsystem running even when no hand is tracked.
- **Regression guard.** `SceneRules` fails content validation when the modality manager has no hand objects or the pinch rays are not under them.
- **OpenXR features: no change.** Lines additionally enables `MetaQuestTouchPlusControllerProfile`, `MetaQuestTouchProControllerProfile`, `OpenXRCompositionLayersFeature` and `DisplayUtilitiesFeature`; none of them affects hands (the first two are controller profiles, ADR-0021 binds the Touch layouts it needs). Every hand feature Lines uses (`HandTracking`, `MetaHandTrackingAim`) is already in `QuestProjectSetup`, plus `HandInteractionProfile`, which XRI's default hand bindings also read.

## Consequences
- Hands render over passthrough, switch with the controllers, and drive the Settings panel (ray + pinch, or poke) and the Nubi poke. Pinching while a hand ray hovers UI no longer talks.
- About 104 extra joint debug objects per session (the visualizer's debug joints, renderers off) and one more transparent draw per tracked hand.
- The rig's behaviour now depends on sample scripts in `Assets/Samples`. Updating XRI or XR Hands means re-importing both samples and re-applying the prune.
- Licensing: the XRI sample is under the Unity Companion License and is committed. The XR Hands *HandVisualizer* sample is under XR Hands' Unity Package Distribution License (distribution only inside a built app), so it is never committed: `Assets/Samples/XR Hands/` is in `.gitignore` and restored from the package we already depend on. `tools/ci/restore-samples.sh` copies `Library/PackageCache/com.unity.xr.hands@<manifest version>/Samples~/HandVisualizer`, `.meta` files included so the GUIDs the scene references match, before every editor run in `tools/ci/test.sh`, `tools/ci/build.sh` and `tools/device/build.sh`. On a fresh clone the package cache does not exist until Unity resolves packages, so the `[InitializeOnLoad]` `Jolly.Editor.Build.PackageSampleRestore` makes the same copy on the first Editor load and refreshes the AssetDatabase. A newer XR Hands lands in a new version folder; the restore follows the manifest.
- Unverified with a wearer when written: hand visuals, ray/poke on the Settings panel, and the pinch gate on the headset. The device log only proves the subsystem runs and the visuals are bound.

## Alternatives
- **Fill the Starter rig's empty hand slots by hand** (our own hand objects, interactors and visual): reimplements the variant without its tested affordances and gesture detectors.
- **Add `com.unity.modules.video` and keep the whole sample:** a new engine module and about 19 MB of demo scene content for nothing the app uses.
- **Meta XR Interaction SDK hands:** ruled out by ADR-0002 (no Meta XR SDK).
