# 0026. Swappable characters: a definition asset per character, local demo skins that never reach git

- Status: accepted
- Date: 2026-11-01

## Context
- The character was Nubi in code: the controller held serialized bone, face-mesh and preset references bound by `NubiPrefabBuilder`, `FaceRenderer` wrote blendshapes by Nubi's shape-key names, and the agent, collider and shadow sizes were constants in the builder.
- For the demo the user asked for a copy-like "Jolly" (Meta's Muse mascot) as a skin, while the public repository keeps shipping Nubi (ADR-0011). Anything derived from the unlicensed `Meta+Muse+Jolly*` source must stay out of git: the FBX, textures, materials, controllers, the definition and every `.meta`.
- So the swap must work without any committed asset referencing the local character, and must fall back to Nubi when the local files are missing (CI, a fresh clone, a broken export).

## Decision
- **`CharacterDefinition` (ScriptableObject, `Jolly.Character`)** holds everything character-specific: `id`, `displayName`, `nameKey`, `model`, `animatorController`, `avatar`, `clips` (canonical name → clip), `facePresets`, `faceMesh`, `face` (canonical channel → blendshapes with weights, plus a jaw share), `jaw` (bone and open rotation), `bones` (chest, neck, head, eyes, upper-body mask root), body (`scale`, `height`, `agentRadius`, `colliderRadius`, `contactShadowRadius`) and `tuning` (the former serialized `NubiCharacterSettings`). Nubi's values moved from the prefab and the builder into `Content/Character/Nubi/NubiCharacter.asset`.
- **Canonical names are the contract.** Clips: `CharacterClips.Required` (Idle, Walk, Hop, Sad, Talk, Listen, Think and every gesture clip: Wave, Nod, ShakeHead, Shrug, Point, Happy, Stretch) and `Optional` (Surprised). Face channels: `FaceChannels.ShapeNames` (sil, A, I, U, E, O, Smile, Frown, Blink_L, Blink_R, Happy_Eyes, Wide_Eyes, Sad_Eyes). Animator states carry the canonical clip names, so face presets, gestures and the expression selector are character-agnostic; `FaceRenderer` maps channels through the definition, so different shape-key names or a jaw-bone mouth work.
- **One shell, swapped model.** `Nubi.prefab` (in Main.unity, with the voice child, interactable and collider the scene binds) is the shell for every character. `NubiCharacterController.TryUse(definition)` instantiates the other model under it, binds it by name (`CharacterRig`), and only then destroys Nubi's model; on failure nothing changes. `Construct` sizes the body from the definition (`CharacterBody`). The class keeps its name: a rename touches `SceneRefs`, the scene, the prefab builder, the test rig and branches in flight (`feat/mr-room-awareness` edits the controller) for no behaviour, and the obvious name `CharacterController` collides with `UnityEngine.CharacterController`.
- **Selection** (`CharacterSelection`, run by `JollyBootstrap` before the graph is built): the id in `persistentDataPath/character.txt` (adb, or Jolly/Character/Play As Selected Definition in the Editor), then the id baked by `build.sh --character`, then `JollyConfig.defaultCharacter`. Unknown, unusable or unbindable choices are logged (`evt=character.unknown|unusable|bind_failed`) and fall back; nothing throws.
- **Local characters live in the git-ignored `Assets/Jolly/Local/`.** `JollyConfig.characters` lists committed characters only (the validator fails a config that references `Local/`). `CharacterSceneProcessor` (`IProcessSceneWithReport`) writes local definitions into `JollyBootstrap`'s `CharacterChoice` in the processed copy of the scene only, so the saved Main.unity never references them: in Play mode all local characters are offered; a player build gets none unless `-nubiCharacter <id>` names one (also its baked default), and an id that matches nothing fails the build. A submission build from a machine that has the local skin therefore does not ship it (verified, below).
- **Contract checks.** `CharacterDefinitionValidator` (Editor.Character) checks clips, controller parameters/layers/clips, presets, bones, face bindings against the mesh, ≤ 4 bone influences, body and tuning values, and warns above 30k triangles. The content validator runs it on every definition in the project (local ones too, when present), so `tools/ci/test.sh` gates it. `CharacterDefinitionTests` runs it per definition and `Assert.Ignore`s the documented local Jolly definition when it is absent. These tests live in PlayMode: EditMode tests reference no Character assembly (architecture §2).
- **Import.** `NubiModelPostprocessor` became `CharacterModelPostprocessor`: any FBX with a sibling `<Model>_FacePresets.json` gets the character import settings. `NubiAnimatorBuilder` became `CharacterAnimatorBuilder` and builds any definition's controller and upper-body mask.

## Consequences
- A new character is a model, a preset file and a definition; no code (docs/characters.md).
- `Jolly.Editor` now references `Jolly.Character` and `Jolly.Editor.Character` (architecture §2, `AssemblyGraphTests`).
- Persona prompts, canned lines (baked audio) and `TranscriptAliases` still say "Nubi". `nameKey` is stored but not read yet; a swapped-in character introduces itself as Nubi until those become name-templated. Voice is per persona and locale (`LocaleVoiceMap`), not per character, so the definition has no voice field.
  - Update: the name is templated now. String tables and the canned-line catalog say `{name}`; `CharacterNamedLocalizer` (Core) wraps the localizer and fills in the selected definition's `displayName` (or its `nameKey` entry in the `UI` table), so persona prompts, greetings, canned lines and stop fillers say it. The name is fixed for the session, so each character keeps one stable prompt-cache prefix. ASR aliases come from `CharacterDefinition.aliases`. Lines that say the name are baked per character into `CharacterDefinition.lineClips` (`CannedLineBaker.BakeCharacterBatch`); `CharacterLineClips` plays only the character's own clip for those and the shared `LineClips` for the rest, so a character never plays another's name. Tool descriptions and the memory summariser no longer name the character. The local Jolly skin lives at `Local/Characters/Jolly/` with `JollyCharacter.asset` (docs/art/jolly-demo.md).
- A runtime-instantiated model gets shadows and motion vectors off, as the prefab builder sets them for Nubi.
- Verified with two Quest APK builds of a throwaway local character (a copy of Nubi's FBX, presets and definition under `Local/Characters/Test/`, id `test`): `build.sh --character test` listed `Local/Characters/Test/Test.fbx`, its presets and its definition in the build report's used assets; the next build without `--character` (incremental, 34 s) logged `local=0` and listed nothing under `Local/`, so the processed scene is not reused across builds. Not yet checked on the headset: `evt=character.selected id=jolly` in logcat.

## Alternatives
- **`Resources/` for local characters:** no committed reference needed, but `Resources.Load` is banned by `tools/ci/test.sh` and loads everything in the folder.
- **An Addressables group for local characters:** the group is registered in the committed `AddressableAssetSettings`, so a local skin would dirty a tracked file.
- **Temporarily editing `JollyConfig.asset` during the build:** a crashed build leaves a tracked file referencing a git-ignored asset.
- **A prefab per character, instantiated instead of the scene's:** the scene binds the voice child, interactable and collider on the instance; swapping only the model keeps those bindings.
- **`AnimatorOverrideController` over Nubi's controller:** the upper-body masks are transform-path masks built from Nubi's hierarchy, so another rig needs its own mask and hence its own controller anyway.
