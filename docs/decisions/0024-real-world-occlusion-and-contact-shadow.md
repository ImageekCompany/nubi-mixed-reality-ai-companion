# 0024. Real-world occlusion (environment depth, scene-mesh fallback) and a contact shadow that follows the feet

- Status: accepted (pending the device checks in `docs/release-checklist.md`, human action 10); the rejection of `ZTest Always` amended for captions and tool badges by [ADR-0050](0050-demo-layout-from-the-measured-window.md)
- Date: 2026-11-01

## Context
- Nubi is a mixed-reality character: it must read as standing in the user's room, seen through passthrough. Until now every real object and the user's own hands were drawn *behind* it, because nothing told the GPU where the room is. Scope item "Should 3" (depth-only occluders from planes/boxes) was not built (architecture §5.5).
- Grounding already existed: `Jolly/Character/BlobShadow` on a quad under the root (CHANGELOG WP6). It never reacted to the feet, so hops (`Hop` gait, `HappyBounce`) left a full shadow under an airborne body.
- Passthrough composition: the camera clears to solid `(0,0,0,0)` (the rig camera, `m_ClearFlags` overridden to 2 in `Main.unity`, `m_BackGroundColor.a: 0`), and the eye buffer's alpha is what lets the passthrough underlay show (`BlobShadow.shader` header). Any pixel that ends with alpha 0 shows the real room.

## Decision
- **Primary: Quest environment depth through AR Foundation shader occlusion.**
  - `QuestProjectSetup` enables `AROcclusionFeature` (Android), and the committed OpenXR settings have it on. Hand removal stays **off**: the hands in the depth map are what hides Nubi behind the user's hands.
  - `Main.unity`'s Main Camera gets `AROcclusionManager` (environment depth Fastest, temporal smoothing requested) and `ARShaderOcclusion` (sources EnvironmentDepth, mode **Soft** so the preprocess shader ships), both **disabled**. `PermissionGate` enables the manager with the other scene managers once `USE_SCENE` is granted; `RealWorldOcclusion.DepthManager` hands it over only when `JollyConfig.occlusion.preference` is EnvironmentDepth.
  - Nubi's own shaders do the test (`Content/Rendering/Shaders/EnvironmentOcclusion.hlsl`, included by `NubiSkin` and `BlobShadow`, `multi_compile _ XR_HARD_OCCLUSION XR_SOFT_OCCLUSION`): project the world position with the eye's depth matrix, compare metres with a 4 cm bias (Nubi's soles touch the sensed floor), and return a visibility. Hard: one point sample. Soft: Meta-style edge blend from the preprocessed texel: visible in front of the near surface, hidden behind the far one, and in between visible by the share of the neighbourhood on the far side, `(avg - near) / (far - near)`. Outside the depth frustum, or with `_IsOcclusionOn == 0`, everything is visible.
  - Output: `NubiSkin` stays opaque and writes premultiplied `(colour × v, v)`; `BlobShadow` multiplies its alpha by `v`. A hidden pixel ends with alpha 0, i.e. passthrough. **Draw calls are unchanged**: no extra pass, no transparency sorting, early-Z intact (no `clip`).
- **Fallback: occluder boxes from Space Setup bounding boxes (Should 3).** `SceneOccluders` keeps one child cube per `ARBoundingBox` (unit cube scaled to `size`, centred on the box pose like `FloorNavMeshBuilder`'s colliders) with `Jolly/XR/DepthOccluder`: queue `Transparent-1`, after Nubi (`Geometry`) and its shadow (`Transparent-10`), `ZTest LEqual`, `ZWrite Off`, `Blend Off`, output `(0,0,0,0)`. Where a box is nearer than Nubi it overwrites Nubi with the clear colour, i.e. passthrough; the floor-level shadow is covered only where a box is in front of it. Because it writes no depth and the world-space UI draws after it (TMP and `UI/Default`: queue `Transparent`, `ZTest [unity_GUIZTestMode]`, LEqual on a world-space canvas), captions, the settings panel, the status indicator and tool badges test only against Nubi, as in depth mode. Planes are not used: the boxes cover tables and couches, the floor plane would clip the feet, and Nubi never walks behind a wall.
- **Selection** (`OcclusionPolicy`, pure): depth while a depth frame with poses arrived within `depthStaleSeconds` (0.5 s), else scene meshes if `sceneMeshFallback`, else nothing; `SceneMeshes` and `Off` preferences force their mode. The sources are exclusive, because a box is larger than the furniture in it and would cut Nubi where depth sees air. "No recent frame" covers a denied `USE_SCENE`, Quest 2 or another runtime, the Editor and a stalled provider in one rule. The boxes help only where `USE_SCENE` was granted (Quest 2, a stalled provider, the `SceneMeshes` preference): `PermissionGate` gates `ARBoundingBoxManager` on the same permission, so with it denied the mode is `scene_meshes` with zero occluders and Nubi is not occluded. `RealWorldOcclusion` (Jolly.XR) applies it each frame, enables `ARShaderOcclusion` only in depth mode and sets its hard/soft mode right before enabling (the setter flips global keywords at once), subscribes to `frameReceived` only once the manager has a subsystem (the Editor NRE above), and logs `evt=occlusion.mode mode=depth|scene_meshes|none`.
- **No Core port.** Nothing in Core needs to know about occlusion; it is wiring between XR and rendering. Settings live in `JollyConfig.occlusion` (`preference`, `softEdges`, `sceneMeshFallback`, `depthStaleSeconds`), so the expensive path can be switched off without a code change.
- **Contact shadow.** `ContactShadow` is a plain part of `NubiCharacterController` (LateUpdate, after the face). The quad stays a child of the root, which the NavMesh agent (or `NubiPlacement`) holds on the floor, so it already sits at floor height under Nubi. It reads the animated `Foot_L`/`Foot_R` bones: lift = lower foot above its bind-pose rest height (`footRestHeight`, 0.06 m for Nubi; since ADR-0026 the feet are `CharacterDefinition.bones.footLeft`/`footRight` and the rest height is read from the model asset's bind pose when the character is bound), and `ContactShadowMath` fades opacity linearly to 0 at `fadeHeight` (0.3 m) and shrinks the quad to `scaleAtFadeHeight` (0.6). Walking keeps one foot planted, so only both-feet airtime changes it. Opacity goes through a `MaterialPropertyBlock`, written only when the shape changes.

## Consequences
- Tests (PlayMode assembly; the EditMode assembly may not reference `Jolly.XR` or `Jolly.Character` per `AssemblyGraphTests`, so their pure logic is tested there as plain `[Test]`s, like `CharacterMathTests` and `PolygonTriangulatorTests`):
  - `OcclusionPolicyTests` (mode table, stale window), `ContactShadowMathTests` (lift, fade, clamp);
  - `SceneOccludersTests` (box volume, resize, visibility of later boxes, removal, cube winding, occluder shader compiles, occluder queue after every Nubi material and before every world-space UI graphic);
  - `RealWorldOcclusionTests` (no depth → scene meshes, depth frames through `NotifyDepthFrame` → shader occlusion on in the configured hard/soft mode and boxes hidden, stale depth → boxes and back, manager left to `PermissionGate`, Off/fallback off hide nothing, construct-once);
  - `ContactShadowTests` on the real prefab (bindings, standing, lifted body fades and shrinks, recovery);
  - `MixedRealityWiringTests` boots `Main.unity` through `AppHarness`: occlusion constructed, scene-mesh fallback in the Editor, shadow bound.
- **Invariant:** the XR Origin stays at the identity pose. The depth poses are documented as world space; with the origin at identity, tracking and world space are the same either way. Moving the rig requires re-checking the projection.
- **Performance** (speculation until measured; DoD §4 budget 13.9 ms/frame at 72 Hz):
  - Depth, soft: one immediate-mode preprocess draw per frame over the depth texture (two slices, five gathers per texel) plus a 64-bit-per-texel array RT; per Nubi pixel one matrix multiply and one sample. Expected well under 0.5 ms GPU on Quest 3 for the app; the runtime's own depth generation is system-side and is what the device measurement must bound. Hard mode drops the preprocess pass.
  - +3 shader variants per Nubi shader (keywords). `QuestVulkan.graphicsstate` was recorded without them, so the first depth frame compiles pipelines until the collection is re-recorded with depth on (`docs/perf/README.md` §7).
  - Scene meshes: one draw per bounding box (typically 3–10), the same material and mesh; well inside the 200 draw-call budget (12 today). Nubi's pixels behind a box are shaded and then overwritten (no early-Z rejection), a small cost for one character.
  - Shadow: same single draw; the property block takes it out of the SRP Batcher (one SetPass at most).
  - Main thread: one subscription callback and the policy per frame, no allocations of ours. `ARShaderOcclusion`'s per-frame callback is package code and is on the device checklist for GC.
- **Unverified until the device run** (release checklist, human action 10): depth texture orientation (no `uv.y` flip is applied; Meta's own Depth API samples the same way), alignment and edge quality, hands, the 4 cm bias against the floor, box pivot = centre, the fallback on a runtime without depth, no occluders after a denied `USE_SCENE`, GPU cost, stale frames, and GC.
- Without depth there is **no hand occlusion**: the boxes are furniture only.
- `NubiPrefabBuilder` rewrites `Nubi.controller` with new local file ids on every run; this change keeps the committed controller and only the prefab diff.

## Alternatives
- **Meta XR SDK `EnvironmentDepthManager` + Meta's occlusion shaders:** excluded by ADR-0002 (OpenXR + meta-openxr only).
- **AR Foundation sample shaders copied in:** they are not in the package (`shader-occlusion.md:36`); Nubi's shader is hand-written and small, so the ~40 lines of depth test live in one include instead of a second lit shader.
- **Depth compare with `clip()`:** costs early-Z on a tile GPU and gives aliased edges; writing visibility into alpha gets soft edges for free from the passthrough composite.
- **Transparent Nubi for soft occlusion:** needs sorting against the shadow and the UI and loses depth write; the opaque-with-alpha output gives the same composite.
- **Both sources at once:** boxes over-occlude where depth is accurate.
- **Depth-only boxes before Nubi** (`ZWrite On`, `ColorMask 0`, queue `Geometry-1`): the first version. The UI's LEqual test then failed behind every box too, hiding captions and panels behind furniture. Overriding the UI to `ZTest Always` would need copies of the TMP and UI shaders (the test is `[unity_GUIZTestMode]`, set by the canvas, not a material property) and would draw the UI over Nubi; a layer split does not help, since the depth buffer is shared.
- **Room-mesh (`ARMeshManager`) occluders as the fallback:** an extra feature, permission path and per-room triangle cost for walls Nubi never walks behind.
- **A real-time shadow map:** architecture §11 allows only the blob; it would cost a shadow pass for one character and still need a passthrough-darkening receiver.
