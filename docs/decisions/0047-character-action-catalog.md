# 0047. The character's body actions are a tool namespace that follows from its clips

- Status: accepted
- Date: 2026-11-02

## Context
- Asked "show me how to dance", "jump!" or "go stand behind me", Jolly could only answer in words or reach for `play_gesture`, whose seven upper-body gestures are expressive punctuation, not things the user asks for. A model told nothing about a body also claims moves it never made: in the namespace probe (ADR-0048) it answered "Go stand behind me" with "I'm behind you now" and no call.
- Characters are swappable (ADR-0026) and each comes with its own clips. The clips agent's `66cd24d` added `Dance` (4 s loop), `Jump` (1.33 s, feet 0.20 m off the floor) and `Bow` (2 s) to Nubi and the local Jolly; a future character may not have them.
- The Responses API groups tools in a `{"type":"namespace"}`; eager namespaces cost about 0.1 s and were chosen reliably, the call comes back as `actions.dance` (live probe 2026-11-02, ADR-0048). The contracts for namespaces (`ToolNamespace`, `IToolRegistry.RegisterNamespace`, `ModelRequest.Namespaces`) were committed in `04af35c`.
- The Gesture layer is masked to the upper body (`bones.upperBody`, `Spine` and below). Played there, a jump keeps its legs on the floor and a dance loses its hips and foot taps.

## Decision
- **An MCP-like action catalog.** `CharacterActionCatalog.For(character, …)` builds the active character's actions as tools in the namespace `actions`, once, in `ToolCatalog.Build` (the character is chosen and constructed before it runs). It is the character's complete repertoire: everything its body does on request. The model sees one namespace and calls `actions.<verb>` like any tool. The namespace description names no action ("Things your body can do, one tool each. When the user asks you to do one, or asks whether you can, call it in this turn to show them; never say you did it without calling it. When they ask you to surprise them, show off or do a trick, pick one or two of these yourself and call them."): seated mode and a persona's tool list withhold actions per request, and a list fixed at startup named moves the request did not offer. Each tool's own description says what it does. Adding an action is one `Offer` line (a `GestureActionTool` for a clip).
- **Availability follows the clips.** `ICharacterController.CanPlay(GestureId)` is true when the character's Animator has the gesture's state, read once from the controller (`Animator.HasState`). An action is offered only when the character can play every gesture it needs; `actions.spin` and `actions.move_relative` need none of the optional clips. Startup logs `evt=actions.offered count= tools=`.
- **Actions (v1):**
  - `actions.jump {}`, `actions.bow {}`, `actions.celebrate {}` (Jump then Happy): `GestureActionTool`, awaited to the end so the model speaks after the move.
  - `actions.dance {duration_s? 2–12, default 4}`: `ICharacterController.PlayLooped(Dance, seconds)` until the first loop end at or after `duration_s`. A new `GestureHold` Animator bool keeps a looping gesture state from leaving; its exit time (below 1) is checked on each loop, so the dance ends where a loop ends, never mid-move. The driver releases the hold as the last wanted loop begins, so the default 4 s is one 4 s loop (about 4.1 s with the fades). Releasing it once `duration_s` had passed, as first built, landed after that loop's exit point and ran a whole second loop: the default dance lasted about 7.8 s. No `style` parameter: there is one dance clip, and a style the body cannot show would be a promise.
  - `actions.spin {turns? 1–3, direction? left|right}`: procedural. `SpinMotion` turns the root by the requested degrees over 1.2 s per turn with smoothstep easing while Happy plays; attention is off during the spin and brings the body back to the user after it (ADR-0041).
  - `actions.move_relative {direction: front|behind|left|right|closer|away, distance_m? 0.5–3, default 1}`: `RelativeTarget` resolves a floor point from the user's head yaw only (front/behind/left/right at `distance_m` from the user; closer to 0.7 m from the user; away backs off along the user → character line). The point snaps to walkable floor within 0.5 m and must stay 0.5 m from the user (the tap-target minimum, ADR-0044); otherwise the tool says `unreachable`, and "closer" when already close says `already_close`. Locomotion concurrency, returns when the walk starts, watches the user so it ends facing them. Withheld in seated mode with `walk_to`.
  - **Never through the user.** When the straight line to the target passes within 0.6 m of the user's floor position ("behind me" from in front of them), the walk goes round them by way of a turn point 1 m beside the user, square to the walk, on the side the character starts on (else the other side). A turn is used only if, once snapped to walkable floor, both legs keep 0.6 m from the user (a character already nearer than that may walk out to it); a turn snapped in closer is rejected, and with neither side usable the tool says `unreachable`. Both legs are **one locomotion command**, `ICharacterController.TryStartMoveVia(waypoint, target, stopDistance, minUserDistance)`: both are planned up front, `eta_s` covers both, `WhenArrived` resolves only at the target, and a stop or newer walk ends the whole motion. At the turn (reached 0.15 m short of it, since turning further short pulls the second leg in) the locomotion checks the second leg's straight line again against where the user is then; if it would pass within 0.5 m, the motion ends there `Unreachable` instead of walking into them. As first built, the second leg was a separate walk started when the first arrived, so `WhenArrived` (the self-test's `action_move_behind` and any other awaiter) resolved at the turn. The NavMesh has no obstacle for the user (their position changes every frame and other tools walk right up to them), so the tool plans round them itself.
  - **Gestures (overlap decision).** `actions.wave`, `nod`, `shake_head`, `shrug`, `think`, `bounce` (the Happy clip), `stretch` and `look_around` wrap the existing gestures one tool each. They are upper body, Parallel, and never stop a walk, so "come here" with a wave still walks. `play_gesture` is removed: the self-test and the eval never depended on it, and two paths to a wave made the model choose between equivalent tools. Its `point` (no target to point at; `look_at` points the head) and the enum argument are gone. The Psychologist persona lists `actions.wave`, `nod`, `shake_head`, `shrug` and `think` instead of `play_gesture`, and no whole-body action.
  - **Whole-body actions and walking never overlap.** A clip or spin played while the agent walks slides the character across the floor mid-jump. One policy, stated in `BodyAction` and `ICharacterController`: a whole-body action (jump, bow, celebrate, dance, spin) **lets a walk to a spot arrive first** (bounded: each of these tools' timeouts has 10 s added for it), and **ends following**, which never arrives; a jump while following leaves the character standing there until asked to follow again. **A walk that starts during a whole-body action ends the action first**: the controller does this on every successful `TryStartMoveTo`, `TryStartMoveVia` and `Follow`, so it holds for a later `come_here` in the round, a tap to move and follow alike, and the action then reports `{"status":"interrupted_by_walk"}` instead of `done`. So `[move_relative, dance]` walks, arrives and dances, and both results are true ("walking", then "done"); `[dance, come_here]` starts the dance, the walk ends it, and the model is told so. First built, the action stopped the walk instead: `move_relative` had already told the model "walking" and the character never went, and a walk started during a dance played the dance while sliding.
  - `come_here` and `move_relative closer` overlap; both are correct for "come closer".
- **Concurrency.** Whole-body clip and spin actions are `Exclusive`, so "jump and then spin" plays one after the other in a round; the upper-body gestures are `Parallel`; move_relative is `Locomotion`.
- **Animator.** Full-body gestures (`GestureClips.IsFullBody`: Dance, Jump, Bow) play on a new unmasked **Action** layer above Gesture, with an `Empty` state that writes nothing. They are **optional** clips (`CharacterClips.Optional`): the builder wires those the definition has; the validator warns on a missing one and errors only when the model has the clip but the controller does not play it. `GestureId` gains `Dance`, `Jump`, `Bow` at the end (the values are Animator conditions). The Action layer has its own `ActionId` (int) and `Action` (trigger) parameters: sharing `GestureId` and `Gesture` with the Gesture layer, a jump and a nod started in the same frame overwrote each other's id, and a cancelled one's fade reset the trigger the other had just set. Face presets read the Action layer first. Local characters' controllers rebuild with `CharacterAnimatorBuilder.BuildLocal`. `GestureDriver` keeps a separate generation per layer and only an Action-layer play touches `GestureHold`: with one shared generation a nod during a dance ended the dance's awaiter early and cleared its hold, and `actions.dance` reported done mid-dance.
- **Prompt.** When the request carries the `actions` namespace the instructions add: "You have a body: when the user asks you to move or do something one of your actions tools does, call it in this turn; never say or imply you did an action you did not call." A persona with an explicit tool list (Psychologist) offers an action only if it lists `actions.<verb>`.
- **Telemetry and UI.** `evt=action.<verb> … status=` per call; badges `tool.actions.<verb>` (en, pl).
- **Self-test.** `action_dance` ("Show me how to dance!") passes when `actions.dance` ran and the Action layer entered the Dance state; `action_move_behind` ("Go stand behind me.") passes when `actions.move_relative` ran and the character arrived at least 135° off the user's forward (as they faced when speaking), within 1.8 m. The clips name no character, so they serve Nubi and Jolly alike.

## Consequences
- "Dance", "jump", "take a bow", "spin around" and "go behind me" do what they say, and a character's repertoire grows by adding a take with a canonical name and rebuilding its Animator. The same seam would take actions from another source (a remote MCP server, a scripted routine) without the agent changing.
- Fourteen tool definitions in every request in place of `play_gesture`; they and the namespace description sit in the cached prefix, which no longer changes with the character, so after the first turn they cost cached-input rates.
- A dance or bow holds the model's next round until it ends (up to about 12 s for the longest dance, after any walk the round started has arrived); the pre-call phrase covers the start and the comment after it lands when the move is done. A barge-in cancels the turn and fades the move out.
- While the Action layer plays it overrides the Talk pose and gestures, so speaking during a dance keeps dancing (the mouth and face still move).
- The model can still answer a question about an action in words: "Can you jump?" passed once in four eval samples (the namespace says "or asks whether you can"; adding the same words to the instructions changed nothing in one more sample, so it was not kept). "Take a bow!", "Stand on my left" and "Do a little show: jump, spin and take a bow" (three calls in one round) passed (docs/perf/tool-selection-eval.md).
- `ICharacterController` grows by three members; both fakes implement them.

## Alternatives
- **More `play_gesture` enum values.** One tool for everything blurs "gesture while talking" with "do this for me", cannot carry parameters per action (duration, direction) and cannot be filtered per character without changing its schema. Rejected.
- **Keeping `play_gesture` beside the gesture actions.** Two equivalent tools for a wave, and the namespace would not be the whole repertoire. Rejected once nothing depended on it.
- **A namespace description listing the offered actions.** Built once at startup, it named `move_relative` to a seated user and every action to a persona that lists two. A per-request list would also change the cached prefix with seated mode. Rejected for a fixed description.
- **A NavMesh obstacle carving out the user.** It would keep every walk off them, but the user moves every frame (carving re-bakes), and `come_here` and `closer` must reach 0.7 m from them. Rejected for the two-leg walk.
- **Deferred namespace loading** (`defer_loading` + `tool_search`). About 0.5 s per load, and with a tight `max_tool_calls` the model loaded the namespace and then claimed the action without calling it. Our action list is short. Rejected for now (ADR-0048).
- **Full-body clips on the Gesture layer with a per-state mask.** Unity masks are per layer; a second layer is the only way. Accepted as the Action layer.
- **Looping the dance by re-triggering one-shot plays.** Each restart fades through Empty, a visible hitch every 4 s. Rejected for `GestureHold`.
- **move_relative in user-relative space from the full head rotation.** Looking down would put "in front of me" at the user's feet. Yaw only.
